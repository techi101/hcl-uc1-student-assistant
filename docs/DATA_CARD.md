# Synthetic data card (Annex E)

All student data is **synthetic**; no real student data anywhere. Generated 6 Oct 2026 by `scripts/generate_data.py`.

| Field | What we did |
|---|---|
| **Purpose** | Exercise every personal / eligibility path of the assistant: attendance tiers (≥ minimum, relaxation band, below the 60% floor), pass/fail by the two NSUT pass rules, ABSENT, DETAINED, backlogs, re-registration after a FAIL, CGPA cut-offs, and an ECE student to prove the CSE-only FAQ never applies to ECE. |
| **Generator** | Groq `openai/gpt-oss-120b`, temperature 0.7, JSON mode. 4 calls (one per programme × batch), 15,760 tokens total, 8–40 s per call. All 4 responses passed validation on the first attempt (retries allowed: 3). Log: `data/students_csv/generation_log.json`. |
| **Prompts** | Verbatim in `prompts/generate_students.txt` (template + model + temperature). |
| **Schema enforcement** | Pydantic models (`CourseRec`, `StudentRec`, `Batch`): ranges for held/attended/marks/CGPA, attended ≤ held, exactly 8 students, every course of the programme exactly once, unique names. Invalid → retry. Then the SQLite schema (`app/db.py`) enforces CHECK constraints again on load. |
| **What code decides (not the LLM)** | student IDs (S1001–S1032), total = internal + external, result PASS/FAIL/DETAINED from `data/rules.csv` (ESE ≥ 30% clause 12.7, total ≥ 35 clause 9.5, attendance < 60% → DETAINED clauses 11.6–11.7), active_backlogs from the latest attempt per course, all edge cases. |
| **Row counts** | 32 students: B.Tech CSE 2023 = 8, CSE 2024 = 8, ECE 2023 = 8, ECE 2024 = 8. 12 courses (6 per programme). 192 attendance rows. 193 results (192 REGULAR 2026-MAY + 1 re-registration attempt 2026-JUL). |
| **Distributions** | Attendance % per course: min 55.0, median 82.5, max 100; 62 rows below 75%, 14 below 60%. Total marks: min 17, median 58, max 95. Results: PASS 148, FAIL 30, DETAINED 14, ABSENT 1. CGPA: min 5.00, median 7.82, max 9.20. Active backlogs: 0 → 21 students, 1 → 3, 3 → 2, 5 → 1, 6 → 5. |
| **Edge cases (student IDs)** | `data/students_csv/edge_cases.json`: S1001 CS201 exactly 80% (threshold in force from 2026-08-01) · S1002 77.5% (one class below 80; HCL's example numbers) · S1003 exactly 75% (Regulations threshold, ask with as_of_date before 2026-08-01) · S1004 72.5% · S1005 55% (below floor → DETAINED) · S1006 ESE 28% with total 44 → FAIL · S1007 total 34 → FAIL · S1008 MA201 ABSENT · S1009 multiple backlogs · S1010 FAIL then re-registration PASS (no supplementary exams at NSUT, clause 12.3) · S1011 CGPA exactly 5.00 (degree minimum) · S1012 CGPA exactly 8.50 (honours) · S1017 ECE EC201 exactly 80%. |
| **Validation results** | `python -m scripts.validate_data --dir data/students_csv` → **0 violations** (`data/validation_report.txt`). Planted-error check: 3 corrupted rows (attended 99/40, bad ID, total ≠ internal + external) → caught, plus the knock-on reference errors. |
| **What the LLM got wrong / what we caught** | (1) The LLM clustered "a few weak students" onto the same people: 5 students fail or are detained in all 6 courses (6 backlogs) — unrealistic; kept and disclosed, not hidden. (2) Our own code bug, not the LLM: exam sessions were sorted as text, so "2026-JUL" came before "2026-MAY" and S1010's re-registration pass did not clear the backlog — caught by `tests/test_tools.py`, fixed with a (year, month) sort, backlog recomputed. |
| **Known limitations** | Both batches take the same semester-3 course list; one exam session (2026-MAY) plus one summer attempt; ESE is assumed to be 50 of 100 marks for every course (theory pattern, Regulations Table 1); no practical/lab components; CGPA is generated, not computed from grades; no placement data (no official placement policy document was available). |
